# 민원 답변 초안(law-draft)·답변 양식·민원 답변 탭

CLAUDE.md 에서 옮겨 온 기록이다(2026-10-14). 이 주제의 코드를 만지기 전에 읽는다.

## 민원 답변 초안 (3단계) — 붙였다 (v130 · 2026-09-06)

법령 탭에서 조문을 고르고 **「✎ 답변 초안」** 을 누르면 초안 창이 열리고,
만든 것을 **「민원 답변」 탭**에 쌓는다. 표는 `answers` 하나뿐이다(SQL: `민원답변-테이블추가.sql`).

- **AI 는 답변을 쓰지 않는다.** Edge Function `law-draft` 가 내는 것은 딱 둘 —
  `summary`(민원 요지 한 문장)와 `help`(실무 참고 한두 문장). **조문 원문은 되뱉지 않는다.**
  브라우저가 갖고 있던 글자를 그대로 끼워 넣으므로 **조문이 틀릴 자리가 구조적으로 없다.**
  형식(1./가. · 머리말 · 맺음말)도 브라우저가 붙인다 — 형식을 바꿔도 AI 를 다시 안 부른다.
- **형식은 「2025 행정업무운영 편람」 기준이다.** 항목 기호 `1. → 가. → 1) → 가)`,
  2타(한글 1자)씩 들여쓰기, 기호와 내용 사이 1타, 끝에 「끝.」. 근거는 기억 폴더의
  `reference-gongmunseo-rules` 에 쪽수까지 적어 뒀다. 화면에서 `가.` 로 바꿀 수 있다.
- **고른 조문은 id 가 아니라 「이름+조 번호」로 저장한다.** 조문 id 는 「조문 전부 다시
  만들기」 때마다 새로 생겨서, id 로 적으면 다시 만든 뒤 기록이 통째로 미아가 된다.
- **한글 파일(hwpx)로 바로 받을 수 있다.** 압축 쓰기(`zipMake`)와 XML 을 직접 만든다 —
  꾸러미를 안 쓴다. 함정은 기억 폴더 `reference-hwpx-export` 에 있다(`linesegarray` 를
  넣으면 줄이 겹친다 · 들여쓰기는 공백이 아니라 문단 여백의 내어쓰기).
- **초안 창은 법령 탭에서 열린다.** 그래서 `renderLaws()` 에도 `#ans-modal` 자리를 두고
  `renderAnsModal()` 을 부른다. 자리가 없으면 **조용히 아무 일도 안 일어난다** — 실제로
  「눌러도 안 열린다」로 한참 헤맸다.

**초안 창은 「바로 고칠 수 있는 글 한 칸」이다 (v154 · 2026-09-09).**
- 「조문만」·「조문 + 도움말」을 나란히 두면 위만 보면 똑같아 보였다 → 판 하나, 참고 붙이기는 체크 하나(`ans-mode`).
- v149~153 은 「초안(읽기만) → 최종본으로 내리기 → 최종본」 두 단계였는데, 내리기 버튼이 `ansSig` 에 안 잡혀
  **눌러도 안 내려왔다**(이랑님 실측). 결국 쓰는 곳은 고친 글 한 칸이다 → 초안 `<textarea>` 하나로 합쳤다.
  복사·텍스트·한글·담기는 **그 칸의 글**로 한다(`ansFinalText/ansFinalBlocks`, 들여쓰기 칸 수로 층을 되읽는다).
  참고 붙이기·형식을 바꾸면 글을 새로 만드는데(`ansRegen`), 손으로 고친 게 있으면(`final≠gen`) 먼저 묻는다.
- **핵심 문장은 규칙으로 고르지 않는다.** v149 의 규칙(검색 낱말이 많은 문장 → 첫 문장)은 제2조에서 「다만…」 단서를,
  제43조에서 「…방지할 것.」 꼬리를 골랐다. 지금은 `law-draft` 가 **Opus 에게 조문마다 한 문장을 원문 그대로 옮기게
  하고(`keys`), 서버가 빈칸을 지워 원문과 대조해 통과한 것만** 준다(12자 미만·400자 초과도 버린다). 못 짚은 조
  (정의·표·목록)는 `""` → 브라우저가 **조문 전체**를 넣는다. 실측: 약사법 제31조③ 은 정확히, 규칙 제2조(정의)는
  빈 값 → 전체. 36원(전엔 23원). 형식 「조문 전체」로 늘 전체를 넣을 수도 있다(`ansFmt.brief`).
  `ansPolite()` 는 「~할 것.」→「~하여야 합니다.」도 바꾼다.
- **근거 문장은 사람이 끌어 고를 수 있다 (v167).** AI 가 짚은 문장은 원문 그대로여도(서버가 빈칸 빼고 100% 대조) 핀트가 빗나갈 수
  있다 — 별표 17 5.2 에서 답인 「타당한 경우 … 허용될 수 있다」 대신 「마.」의 일반 문장을 골랐다(이랑님 「AI 가 뭔가 말을 만들어낸 것
  같지 않음?」 — 만든 건 아니고 덜 맞는 문장이었다). 조 전체 보기에서 글자를 끌어 고르면 아래에 「고른 문장을 답변 근거로」가 뜬다
  (`lawKeyPick[artId]`, `selectionchange`). 담아 갈 조문에 `artId`·`pick` 이 실리고 `ansMake` 뒤 `key` 를 덮는다. 초안 창이 열려 있으면
  즉시 다시 만든다. law-draft 12판: 「되나요」 민원엔 결론·조건·허용을 말하는 문장을 고르라고 적었다.
- **다시 연 답변은 근거 문장을 저장된 글에서 되찾는다 (v168).** 다시 열면 `key` 가 없어서 참고 붙이기만 켜도 조문 전체로
  다시 써졌다(이랑님 「조문 전체를 써버리는데?」). `ansKeyFromSaved()` 가 「조항에서, <문장>고 규정하고 있습니다」에서 문장을 꺼내
  원문과 대조해 넣는다. 근거 칩에 「근거 문장 있음 / 직접 고른 문장 / 문장 없음 → 조문 전체」가 보이고, 칩을 누르면 조 전체 보기가
  열려 끌어 고를 수 있다(`ans-chip-open`, 칩에 `artId·lawId`).
- **실사 노트 「새 본으로 다시 채우기」가 두 번 눌려 줄이 두 배(252)가 됐다 (v168 에서 막음).** `inspBusy` 로 겹침을 막고,
  읽어 올 때 같은 줄(노트·페이지·묶음·글·본)은 체크·메모 있는 쪽만 남긴다(`inspDedupe`). 서버 것은 SQL 로 한 번 정리했다.
- 「민원 답변에 담기」를 누르면 저장하고 **그 탭으로 간다**(`active="answers"`).
- **목록 제목은 핵심 낱말이다 (v157).** 요지 문장을 제목으로 쓰니 한 줄에 안 들어갔다(이랑님 「제목을 핵심 단어로 요약」).
  `law-draft` 가 `title`(「보툴리눔 · 다른 의약품 · 2차 포장 공용」 꼴, 8~24자)을 내고 `ansTitle()` 이 쓴다. 함수가 옛 판이면
  요지에서 「에 관한 것」을 떼고 40자에서 자른다. **다시 열 때 요지는 제목이 아니라 본문 첫 줄에서 되찾는다**(`ansSummaryOf`).
- **목록에서 안 펼치고 요지를 읽는다 (v159).** 제목(핵심 낱말) 아래에 요지 문장(`ansSummaryOf`, 두 줄까지)을 두고,
  근거는 이름 나열 대신 「근거 N건」. 옛 답변처럼 제목이 곧 요지면(앞 24자 같음) 되풀이하지 않는다.
- **처음 초안은 덮어쓰지 않는다 (v161).** 다시 열어 고쳐 담을 때 `draft` 는 처음 것을 두고 `final` 만 바꾼다(이랑님 「고치기 전 글
  어디서 확인?」— 그전엔 덮어써서 사라졌다). 펼치면 「처음 초안 · 다시 열어 고치기 전」과 「고친 글」이 나란히, 둘이 같으면 「답변」 하나만.
  「고친 글 있음」 표시도 둘이 다를 때만. 한 단계만 남긴다 — 판마다 다 남기려면 표에 칸이 필요하다(SQL). 시험대 `?tab=answers&open=<id>`.
- **「다시 열어 고치기」가 빈 칸으로 열렸다 (v157 에서 고침).** 고치지 않고 담은 답변은 `final` 이 null 이라 v154 의 한 칸
  초안이 비었다. 저장된 `draft`, 그것도 없으면 조문으로 다시 만든 글을 넣는다. 시험대 `?tab=answers&reopen=1`.
- **창이 앞으로 올 때마다 다시 그려져 스크롤이 위로 튀었다.** `onResume`(window focus·visibilitychange)이
  render() 를 부르고, 아이패드는 글쇠판만 열고 닫아도 그게 난다. `renderAnsModal()` 은 서명(`ansSig`)이 같으면
  안 그리고, 그릴 때는 `.ans-scroll` 자리를 되돌린다. **모달·입력창이 있는 화면은 다 이 위험이 있다** —
  법령 조 전체 보기(`renderLawModal`)는 `data-sig` 로 이미 막아 두었다.

**답변 양식은 국민신문고 꼴이 기본이다 (v162 · 2026-09-10).** 이랑님이 실제로 고쳐 쓰신 「고친 글」을 그대로 본떴다:
1. 인사(신청번호) → 2. 「'주제'에 대한 질의로 이해됩니다」 → 3. 검토 결과 가./나./다.(「「법령」(식약처 고시) 조항에서, …」) →
4. 담당과·직위·연락처 → 끝. `ansBlocksSinmungo()`. 편람식(`classic`)은 형식에서 고를 수 있다.
- **조문 문장은 원문 그대로 + 존댓말만.** `ansQuoteForm()` 이 「…한다」→「…한다고 규정하고 있습니다」로 감싼다(간접 인용).
  이랑님: 「안녕하다 → 안녕하세요 정도의 수정은 해야 하는데 원문에서 의미가 벗어나면 안 돼」 「할 수 있다가 조문에 박혀 있으면
  그대로 차용해도 상관없어」. AI 가 풀어쓰지 않는다 — 풀어쓰기는 이랑님이 초안 칸에서 한다.
- `law-draft` 가 `topic`(「'반창고 품목허가'에 대한 질의」의 빈칸, 4~16자)을 낸다. 신청번호는 초안 창에서 건마다 적고,
  담당과·직위·전화는 형식에 한 번 적으면 **설정 표(`settings`)에 저장돼 아이패드·맥이 같다**(`ans_fmt`).
- 「고른 N곳 복사」도 같은 꼴의 머리줄(「가. 「법령」(종류) 조항에서,」)을 먼저 둔다.

**「AI에게 알려둔 우리 과 규칙」 (v162).** 왼쪽 아래 단추 → 글 칸 하나(`settings.ai_rules`). `law-pick`(1차·2차)과 `law-draft` 가
프롬프트에서 `<담당자 규칙>`으로 읽는다. 소관 구분·「이 말이 나오면 이 문서」 같은 것은 코드에 박으면 다음 사안에서 또 틀리므로
이랑님이 평문으로 적는다(2026-09-10 사례 정리 문서의 「소관·제도 구분 태그」「키워드→문서 매핑」을 이걸로 갈음). 법령 탭에는
아무것도 안 늘렸다(이랑님: 「법령 탭 안에 뭔가가 너무 많아지는데」).

**근거 고르기 규칙 셋 (law-pick 32판 · law-draft 10판).** 2026-09-10 유전자재조합 CMO 이전 사례에서 나온 것.
① 「…할 수 있다」(재량) 조문만 보고 「필수가 아니다」「재량이 핵심」이라 쓰지 않는다 — 재량을 언제 쓰는지 정한 지침의 구체 기준이
후보에 있으면 그쪽이 인용 필수. ② 질문에 든 낱말(「시험생산 배치」)이 조문의 판단 기준인지 본문으로 확인, 없으면 짐작 금지.
③ **근거 문장이 원문 대조에 실패한 조는 「인용 필수」로 못 올라간다**(서버가 「있으면 좋음」으로 내린다) — 전문수탁 절차 24쪽
「사례 14」가 대조 실패인데 인용 필수로 붙어 초안에 들어갔었다. 「스니펫 매핑 오류」가 아니라 대조 실패 시 본문 앞부분을 보여준 것.

**지난 답변을 본보기로 (v163 · law-pick 33 · law-draft 11 · 2026-09-10).** 이랑님 「제안 좋은 듯」. 손으로 적는 규칙 대신
「민원 답변」 탭에 쌓인 답변을 AI 가 본보기로 쓴다. `answers.emb vector(1024)`(질문 글의 지문, 없으면 law-pick 이 그 자리에서
만들어 넣는다). law-pick 은 이번 질문 지문과 견줘 유사도 0.50 이상 3건까지 골라 ① 그때 인용한 조문(이름+라벨로 찾음)을
후보 **맨 앞**에 넣고 ② 2차에 `<지난 답변>` 으로 알린다(「본보기이지 정답표가 아니다」). 응답 `similar`·`pastBoost`.
앱은 쪽지에 「비슷한 지난 답변: 제목」(누르면 그 답변으로)을 보이고, 초안을 만들 때 그 답변의 고친 글(1,800자)을 `examples`
로 law-draft 에 넘긴다 — 말투·구성·참고의 본보기이고 조문 내용은 옮기지 못하게 했다.
**실측은 아직 못 했다** — Anthropic 월 한도($5)에 닿아 「usage limits… 2026-10-01」이 났다.

**AI 결과와 낱말·뜻 검색 결과는 한 목록이다 (v154).** 「AI 가 고른 것」 묶음과 「낱말로 찾은 것」 묶음을 위아래로
두었더니 체크·복사 버튼이 두 벌이라 스크롤을 오가며 골라야 했다(이랑님). `lawCards()` 가 두 결과를 조문 id 로
합쳐 카드 하나로 만들고(`"a"+artId` 열쇠 하나 · `lawSel` 하나), 머리줄 하나(`.law-head.sticky`)가 위에 붙어 있다.
AI 가 고른 카드는 왼쪽 띠(`.law-hit.has-ai`)와 이유·근거 줄을 더 보인다. 「있어도 됨」인데 낱말에도 안 걸린 것은
접어 둔다(`ask-more`). AI 가 읽은 요지·보강 낱말은 결과 위 쪽지(`lawAskNoteHtml`)에만 남는다.

**「민원 자료」 탭(마스터 문서)은 화면을 없앴다.** 닷새 동안 문서 1개·절 8개만 쓰였다.
`refs`·`ref_parts` 표와 `refUpload`/`refSearch` 등 코드는 **그대로 남겨 뒀다** —
`archive`·`docs` 를 남긴 것과 같다. 되살리려면 `render()` 에 갈림길 한 줄만 넣으면 된다.
