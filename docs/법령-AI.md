## 법령 AI 는 맥의 Claude Code(구독)로 돈다 (v214 · 2026-09-28)

이랑님 「구독료에서 나갈 수 있게 못 해?」 → 「CLI 뚫어줄 수 있어?」 → 「ㄱㄱ」. **토큰을 빼내는 게 아니라 맥의 진짜
`claude -p` 를 돌리는 것** — 구독 토큰을 다른 앱에 끼우는 건 2026-02 에 금지됐지만(계정 제재 사례 있음), 자기 컴퓨터에서
Claude Code CLI 를 스크립트로 부르는 건 Anthropic 이 그러라고 만든 제품이다.

- **흐름:** `law-pick`·`law-draft` 의 `claude()` 가 먼저 `ai_jobs` 표의 심장박동 줄(id `0000…0001`, 45초 안 갱신)을 보고
  맥이 깨어 있으면 일감 한 줄을 넣고(`req: {model, system, prompt, effort, schema}`) 1.5초마다 `done` 을 기다린다(110초).
  맥이 자면 `claudeApi()`(예전 API 길)로 — **실사 출장 중에도 막히지 않는다.** 응답의 `via`(cli/api/mixed)를 화면이
  「맥에서 · 구독(0원)」으로 보인다. `usage` 는 0 으로 돌려 `krw` 가 0 이 된다.
- **맥 일꾼:** `tools/ai_worker.py` — launchd(`tools/com.yakktime.aiworker.plist`)가 로그인 때 띄우고 죽으면 다시 띄운다.
  열쇠는 `~/.yakktime-service-key`(service_role). 기록 `~/Library/Logs/yakktime-ai-worker.log`.
- **`claude -p` 는 반드시 `--system-prompt` + `--tools ""` 로.** 기본 설정이면 코드 도우미용 시스템 프롬프트(약 18k 토큰)가
  딸려가 한 번에 $0.28어치, 이렇게 부르면 $0.002어치(2026-09-28 실측, 3+4 한 줄). 구독이라 돈은 안 나가지만 **이랑님
  주간 한도**를 먹는다 — 그 한도는 나와 일하는 한도와 한 통이다.
- **설치는 토큰 하나로:** `/토큰넣기` → `sh tools/setup_mac_worker.sh` (service_role 열쇠 파일 · `ai_jobs` SQL · 함수 둘 배포 ·
  launchd 등록 · 심장박동 확인). SQL 은 `OPUS 4.8 생성/ai_jobs-테이블추가.sql`.
- 모델 이름은 별칭(haiku/sonnet/opus)으로 넘긴다 — `--model opus` 가 `claude-opus-5` 로 돈다(실측).
- **켰다 (2026-09-30 09:27).** 첫 실측은 78초·9,154토큰 — Claude Code 가 Haiku 에도 「생각하기」를 켜서 8천 토큰을 생각으로
  쓰고 서버 함수 150초 제한에 걸렸다(HTTP 546). 일꾼에 `MAX_THINKING_TOKENS=0`(Haiku 만) + `--strict-mcp-config --mcp-config
  '{"mcpServers":{}}'`(캘린더·메일 MCP 를 매번 붙이지 않게) → **26초·2,613토큰**. 함수는 맥이 65초(초안 100초) 안에 답 없으면
  **그 한 번만 API 로**(throw 하지 않는다). 재실측: 두 번 8.6s+28.3s, 응답 52초, `via:"cli"`, 0원, 지침 24쪽 포함 8건.
- **맥의 Claude Code 로그인(OAuth)이 만료되면 일꾼이 전부 실패하고 조용히 Haiku API 로 간다 (2026-10-12 실측).** 10/9~10 맥이 서버에 못 닿는
  사이 토큰이 만료됐고 launchd 의 `claude -p` 는 「OAuth session expired and could not be refreshed」. 화면엔 「Haiku(Opus 가 못 답함)」·
  153원만 떠서 원인을 알 수 없었다. 이 세션(Claude Code)이 맥에서 돌자 갱신돼 바로 됐다. 「Opus 가 못 답함」이 뜨면 먼저
  `tail ~/Library/Logs/yakktime-ai-worker.log` 를 본다. 남은 일: 심장박동에 로그인 상태를 싣고 만료면 법령 탭에 한 줄 알리기.
- **launchd 가 띄운 프로그램은 iCloud 폴더(Mobile Documents)를 못 연다**(「Operation not permitted」). 일꾼은 `~/.yakktime/`
  에 복사해 돌린다 — `setup_mac_worker.sh` 가 복사하니 **일꾼을 고치면 그 스크립트를 다시 돌린다.** macOS 가 「python3 이
  백그라운드 항목에 추가됨」이라 알리는 게 이것이다(시스템 설정 → 일반 → 로그인 항목에서 끌 수 있다).
- **law-pick 도 Opus 5.5 로 바꿨다 (2026-09-30, 36판, 이랑님 「haiku 는 당장 바꿔줘」).** 거부·잘림·오류면 `askJson()` 이
  Haiku 로 되받는다(`fellBack`). 첫 실측(CMO 이전 질문): 37초 · `via:"cli"` · 0원 · 본문 45개 읽음 — 사전 GMP 평가 지침 8·9·7쪽을
  「매우 높음」으로 잡고 쪽지에 결론(「새 CMO 작업소에 실사 이력이 없으면 실태조사 대상」)을 적었다. **다만 일꾼 기록의 환산값은
  1차 $0.30 + 2차 $0.43 ≈ 1,000원** — 맥이 자서 API 로 가면 한 번에 그만큼 나가고 월 $5 로는 일곱 번이다.
  그래서 **나눴다(37판): 맥이 깨어 있으면 Opus 5.5, 자면(또는 65초 넘게 늦으면) Haiku 로 API.** Opus 는 절대 API 로 안 간다.
  보툴리눔 2차 포장 질문도 Opus 5.5 가 **거부하지 않았다**(41초·0원) — 별표 1 8.2 포장공정관리 · 시설기준령 제2조 「매우 높음」,
  Haiku 가 못 고르던 별표 17 5.7 포장작업도 골랐다.
- (옛 메모) law-pick 은 Haiku 였다. Opus 로 바꾸면 2차(본문 34개 읽기)가 65초를 넘겨 API 로 떨어질 위험(300~600원). 바꾸려면
  먼저 `~/.yakktime` 에서 2차 일감을 Opus 로 재 본다(`/tmp/job_req.json` 같은 저장 요청으로).

## 전에 답변에 쓴 조문은 위로 올린다 (v134 · 2026-09-08)

「민원 답변」에 근거로 담은 조문이 낱말 검색·AI 결과에 다시 나오면 **같은 법령 안에서
맨 위**에 두고 「답변에 씀」 칩을 붙인다(`ansUsedMap()`·`ansUsedChip()`). AI 결과에서는
등급이 낮아도 접지 않는다. **새 버튼은 없다 — 저장된 답변이 곧 신호다.**

**체크는 등급으로만 한다 (v135).** v134 는 쓴 조문을 등급과 상관없이 처음부터 체크했는데,
이랑님이 「애매한 것도 다 차용하게 하는 게 좋나」고 물었다. 맞는 지적이다 — 이 칩은
**질문이 비슷한지 보지 않는다.** 저장된 답변 어디엔가 그 조문(이름+조 번호)이 인용됐다는
것뿐이다. 그래서 자리·칩·펼침까지만 하고, 이번 질문에 맞는지는 사람이 체크한다.

- **열쇠는 id 가 아니라 이름+조 번호**(`ansUsedKey`). 조문 id 는 「조문 전부 다시 만들기」마다
  바뀌므로 답변에도 id 가 없다. 이름은 빈칸을 빼고 견준다 — AI 가 주는 `p.law` 와
  `lawName()` 이 같은 `laws.name` 에서 오지만, 빈칸 하나에 못 맞추면 억울하다.
- **위계·법령 순서는 안 건드린다.** 지침서의 쓴 조가 법률 위로 올라오면 근거가 약한 것을
  먼저 보게 된다. 묶음 안에서만 앞으로 온다.
- **「중간 이상 N곳」은 등급으로만 센다.** 펼친 개수로 세면 쓴 조문이 끼어 숫자가 어긋난다.
- 시험대: `mocksb.js` 의 USEDTEST 가 답변 3건을 더 넣는다. `?tab=laws&q=낱말` 로 낱말 검색을
  바로 띄울 수 있다(2026-09-08 추가).

## 소관 판단 한 줄 — 「내부 규정」 묶음 (v220 · 2026-10-06)

이랑님(바이오의약품품질관리과 안의 바이오의약품품질인증TF — 같은 과) 「내가 어떤 과에 있는지 먼저 체크하고 내가 답변할 게 맞는지」.
- 「식품의약품안전처와 그 소속기관 직제 시행규칙」(총리령, 과별 분장)·「식품의약품안전처 민원 처리에 관한 규정」(훈령, 제7조 분류 기준)을
  받아 **「내부 규정」 묶음**(`LAW_GRP_INTERNAL`)에 둔다. 답변 근거가 아니다 — `lawScopeIds()` 가 평소 범위에서 뺀다(조문 찾기·낱말·뜻 검색 모두).
- `law-pick` op:"triage": 분장 조문(식품 쪽 제외, 12조·약 9만 자)과 제7조를 주고 `{owner, ownerBasis, coop[], local, mine, note}`.
  앱은 조문 찾기와 **동시에** 부르고(`lawTriageAsk`) 쪽지 맨 위 한 줄(`lawTriageHtml`). 내 과는 설정 `my_div`(없으면 바이오의약품품질관리과).
- 민원처리 규정 제7조: 둘 이상 부서면 가장 관계 많은 부서 하나 · 재분류 순서 ① 직제 분장 ② 항목 수·난이도 ③ 종전 처리부서 ④ 상위 서열 ⑤ 협의.
- 분장에서 자주 쓸 것: 바이오의약품품질관리과 1호 GMP 기준 · 17호 **제조업 시설기준 관리** · 19호 장기추적조사 / 의약품관리과 11호 KGSP(규칙 별표 6).
- **「시설 기준이라 애매」는 틀렸다** — 17호가 우리 과다. 개별 허가·적합 판단만 지방청(첨단바이오 규칙 제9조 소재지 관할 지방청장).

## 협조 질의는 우리 몫 갈래만 찾는다 (v222 · law-pick 39 · law-draft 16 · 2026-10-12)

이랑님 「1번 질문이 왜 우리과 꺼야? 협조 질의가 들어오면 우리가 답변할 조문만 찾도록 프로세스가 하나 더 있어야」.
계획·실측은 `계획/협조 질의 — 우리 몫만 찾기 계획 2026-10-12.md`.
- **차례가 바뀌었다: 소관 판단 → 조문 찾기.** 전에는 둘이 동시에 돌아 조문 찾기가 다섯 질문 전체로 갔다. 이제 `lawAskRun` 이
  `lawTriageAsk` 를 기다린 뒤 `lawPickRun` 을 부르고, 우리 몫이 아닌 갈래가 있으면 `lawFocusText()` 가 「배경 + 켜진 갈래」만 보낸다.
  소관 판단이 실패하면 전체로(막히지 않는다). 우리 몫이 없으면 AI 를 더 안 부르고 「그래도 민원 전체로 찾기」만 둔다.
- **소관 판단이 질문 갈래마다 낸다** — `parts[{no,text,gist,owner,basis,mine}]` + `background`. 갈래 글은 원문 발췌여야 하고 서버가
  빈칸 빼고 대조한다(`verbatim`). 화면은 칩(`.tri-part`) — 누르면 켜고 끄고, 바꾸면 「이 갈래로 다시 찾기」.
- **내 자리는 설정에만 있다 — 코드에 과 이름을 두지 않는다**(이랑님 「과를 옮겨 다니면서 분장이 바뀔 것도 고려」). `my_div`(직제 이름 그대로) ·
  `my_role`(과 안에서 맡는 범위 평문). 규칙 창(「AI에게 알려둔 우리 과 규칙」) 맨 위 두 칸. 과 이름을 적으면 `rulesDivCheck` 가 직제
  시행규칙에서 「분장 N호」를 찾아 보여 준다 — 틀리면 소관 판단이 통째로 틀리므로 바로 알린다. 과 분장이어도 `my_role` 밖이면
  「아님」(인체조직·원료혈장은 과 분장이지만 바이오의약품이 아니다). 과를 옮기면 이 두 칸과 규칙만 고친다.
- **초안은 협조 꼴로** — `ansDraft.tri`(`ansTriOf`) 가 있고 다른 과 갈래가 있으면 `coopIntro·coopAsk·coopReview·coopSkip·coopClose`
  (형식 창에서 고침). 초안 창 칩을 누르면 주관 꼴로 바꾼다. `law-draft` 에 `scope` 한 줄을 넘겨 요지·주제가 우리 몫만 말한다.
- 실측: 소관 28초 · 조문 40초 · 둘 다 Opus 맥 0원. 1~3 정책과 「아님」, 4·5 「협조」. 우리 몫만으로 찾으니 **별표 4의2(임상시험용의약품
  GMP 기준)** 가 인용 필수로 올라왔다 — 전체로 찾을 땐 제7조(허가 제외)가 앞을 차지했다.

## 조문 찾는 동안 범위는 잠근다 · 긴 요청은 아이패드 5G 에서 끊길 수 있다 (v224 · 2026-10-12)

- 이랑님 「조문 고르기 하고 나서 다른거 못누르게? 여기서 공통이나 다른거 누르면 거기서만 찾는거 아님?」 — 찾는 동안 묶음 칩·목록 체크를
  `disabled` 로 잠그고(`.law-grps.is-busy`) 「지금 범위로 찾고 있어요」. 범위(`lawAskScopeIds`)와 범위 글은 **누른 순간** 것으로 고정 —
  소관 판단을 기다리는 10여 초 사이에 바뀌지 않게.
- **「물어보지 못했어요: Failed to send a request to the Edge Function」이 떴는데 맥 일꾼 기록엔 그 시각 일감이 전부 「끝」이었다**
  (14:52~14:56 세 번 모두 삼분·1차·2차 완료). 서버는 다 했는데 답이 아이패드에 안 닿은 것 — 소관 판단 → 1차 → 2차 가 한 요청에
  60~70초라 5G 에서 연결이 바뀌면 끊긴다. **함수 로그로 확인했다(10/14, Supabase 커넥터 `query_logs`)** — 14:53~14:56 law-pick 6번
  전부 **HTTP 200**(16~46초, LGTELECOM·HTTP/3), 함수 오류 0건. 15:19 소관 판단도 서버는 18.5초에 200 을 냈다. 서버는 끝까지 했고
  답이 기기에 안 닿은 것 — 일감 방식(v225~228)이 맞는 처방이었다. 로그는 커넥터로 읽는다: `select … from logs where
  source='function_edge_logs'`, 시각은 UTC(한국 −9시간), `log_attributes['execution_time_ms']` 만 골라야 결과가 안 넘친다.
- **→ 일감 방식으로 바꿨다 (v225 · law-pick 40판, 같은 날).** 이랑님 「ㅇㅇ 진행해주고」. 앱이 `job`(uuid)을 주면 함수가 `ai_jobs` 에
  `kind:"pick" status:"running"` 줄을 만들고 **2초 안에 응답**, `EdgeRuntime.waitUntil` 로 마저 돌려 `done`(res = 예전 응답 그대로)/`error` 를
  적는다. 앱은 `lawPickPoll` 이 2.5초마다 읽고(`maybeSingle`), 시작 요청이 끊겨도 줄을 읽어 보며, `localStorage.law_pending`(15분)으로
  닫았다 열어도 이어받는다(`lawPickResume`, 법령 탭 그릴 때 한 번). 일꾼은 `status=queued` 만 집으므로 이 줄은 안 건드린다.
  하루 지난 pick 줄은 시작할 때 지운다. 실측: 시작 응답 2초 · 39초 뒤 done · 조문 9건 · 0원.
- **소관 판단도 같은 꼴 (v227 · law-pick 41판).** 15:19 실측 — 맥은 13.5초 만에 끝냈는데 아이패드는 8초 만에 「Failed to send」로 포기하고
  전체 질문으로 조문을 찾았다(이랑님 「나중에 크리티컬 할 수도」). `kind:"triage"` 줄, 앱은 2초마다 읽고 20초 넘게 줄이 안 생기면 「요청이
  닿지 않았어요」로 넘어간다. 실측(헤드리스, 진짜 코드): 소관 17초 → 조문 38초 → 카드 7 · 소관 줄 표시.
- **초안도 같은 꼴 (v228 · law-draft 17판, 이랑님 「그냥 지금해」).** `kind:"draft-job"` 줄(일꾼의 맥 일감 `kind:"draft"`·queued 와 다른 줄).
  `ansMake` 가 2초마다 읽고 20초 넘게 줄이 없으면 「다시 만들기」 안내. 실측: 16초 · via cli · 0원 · 요지·제목·근거 문장 정상.
  **이제 법령 AI 세 요청(소관·조문·초안)이 전부 일감 방식이다** — 새 AI 호출을 만들면 같은 꼴로(jobPut + waitUntil + 앱 폴링).

## 뜻 검색(의미 검색) — 설계도의 2층 (v144 · 2026-09-08 코드 완성, 열쇠 기다림)

낱말 검색과 AI 의 제목 훑기는 **낱말이 맞아야** 찾는다. 「같이 2차 포장」을 물으면 법령은
「구획」이라 쓰므로 놓쳤고, 이랑님이 「구획 포장을 내가 생각 못해낼 것 같은데」 하셨다.
그래서 조문마다 **뜻 지문(임베딩)** 을 두고, 질문의 지문과 가까운 조문을 AI 후보에 보탠다.
이랑님 판단: 「제일 미래지향적인 방법으로 — 시스템 만드는 건 불편해도 괜찮음」.

- **Voyage AI `voyage-4-large`** 1024차원(Anthropic 이 권하는 임베딩. Anthropic 자체에는 없다).
  요청 하나에 12만 토큰까지, 입력 1,000개까지. **200M 토큰까지 무료** — 조문 1,349개 전체가
  150만 자쯤이라 백 번을 다시 만들어도 무료 안이다. 유료 단계(Tier 1)는 결제수단을 넣어야 열린다.
- **표:** `law_articles.emb vector(1024)` + HNSW 인덱스. 함수 `law_match(q text, k, law_ids uuid[])`
  (코사인 유사도) · `law_emb_put(rows jsonb)`(묶음 갱신). SQL 은 `법령-뜻검색-pgvector.sql`.
  **`only` 는 PostgreSQL 예약어라 매개변수 이름으로 못 쓴다** — `law_ids` 로 바꿨다.
- **`law-embed`**(새 함수): `status` / `run {lawId?, max}`. emb 가 비어 있는 조문을 100개씩 받아
  글자 예산 14만 자 안에서 묶어 Voyage 에 보내고 `law_emb_put` 으로 넣는다. 429 면 `retryAfter` 를
  돌려주고 앱이 쉬었다 이어간다. 지문에 넣는 글: 법령 이름 + 조 이름 + 본문 앞 6,000자(격자 기호 뺌).
- **`law-pick`**: 열쇠가 있으면 질문을 `input_type:"query"` 로 지문 내고 `law_match` 상위 24개 중
  유사도 0.35 이상·이미 후보가 아닌 것 12개까지를 **후보 맨 앞**에 끼운다(예산은 뒤부터 잘린다).
  응답 `semantic` → 화면 「뜻이 닿는 조문 N개를 후보에 더 넣었어요」. 열쇠가 없으면 예전과 똑같이 돈다.
- **앱:** `saveLawArticles` 끝에 `lawEmbedRun(lawId)` — 조문을 새로 만들면 지문도 새로. 목록을 열면
  `status` 를 한 번 물어 지문 없는 조문이 있으면 알림 한 줄(「뜻 검색 준비하기」)로 전부 만든다.
- **켰다 (2026-09-08 22시).** 열쇠는 이랑님이 Secrets 에 넣었다. **결제수단 없는 Voyage 계정은 분당 3회·1만
  토큰**(429 본문에 그렇게 적혀 온다) — 100개씩 보내면 영원히 429 다. `slow:true` 면 3개·7천 자씩 보내고
  부르는 쪽이 21초 쉰다(v145). 실측 분당 4개꼴 → 1,349개에 5시간. 결제수단을 넣으면 2000 RPM 이라 1분.
  첫 채우기는 `scratchpad/embed_driver.py` 로 맥에서 돌렸다(앱을 켜 두지 않아도 되게).
- **실측 (2026-09-09 03시, 1,349개 지문 완성 뒤).** 보툴리눔 2차 포장 질문:
  · 지문 없을 때: 후보에 포장 관련 별표가 하나도 없었다(111원).
  · 원문 지문만: 뜻 후보 12개가 들어가 「별표 2의2 8.2 교차오염 방지」가 잡혔지만 **별표 1 8.2 포장공정관리는
    10위, 별표 17 5.7 포장작업은 36위**라 못 들었다(163원). 민원 원문은 업체 사정·층수가 지문을 흐린다.
  · **1차가 요지(gist) 한 문장을 함께 내고 원문·요지 둘로 찍어 합치자** 「별표 1 8.2 포장공정관리」가 **1순위
    「인용 필수 · 근거 찾음」**으로 올라왔다(161원, 본문 33개 읽음). 별표 17 5.7 은 뜻 후보(7위)에 들었지만
    2차 Haiku 가 고르지 않았다 — 값싼 모델의 한계. 후보에 넣는 것까지가 뜻 검색의 몫이다.
  · 시험은 `law-embed` 의 `query` op 으로 한다(AI 를 안 부르니 0원) — 어느 조문이 몇 위인지 바로 보인다.
- 한 번 값이 111 → 161원으로 늘었다(뜻 후보 12개의 본문을 더 읽는다). 정확도 쪽을 택한 것이다.

**문장을 치고 Enter 면 뜻으로 찾는다 (v147).** 낱말 검색은 낱말 다섯 개(최대)가 **모두** 든 조문만 찾으니
문장을 넣으면 늘 「찾지 못했어요」였다(이랑님: 「문장으로 입력해서 엔터 누르면 너무 길어서 못 찾잖아」).
문장(14자·4낱말 이상)이면 `lawSemSearch()` — `law-embed` 의 `query` op 으로 뜻이 가까운 조문 20개(유사도 0.3
이상)를 카드로 보여준다. **AI 를 안 부르니 0원, 1초.** 낱말로 0건이어도 뜻으로 한 번 더 찾는다(`auto`).
카드 발췌는 본문 앞 260자, 복사는 조 전문. 머리에 「뜻이 가까운 조문 · AI 는 안 불렀어요(0원)」.
AI(✦ 관련 조문 찾아줘)는 지금처럼 눌러야만 돈다 — 돈이 드는 것은 누르게 한다는 원칙 그대로.
실측(이랑님 문장 그대로): 20개 중 별표 17 3.3 작업소 4위 · 시설기준령 제2조 8위 · 규칙 별표 1 8.2 포장공정관리 12위.

## 앞으로 할 일 — 법령 AI 어시스턴트

법령 PDF를 넣어두고 검색하고, AI가 민원 답변까지 도와주는 기능을
**단계별로** 추가할 예정이다.

전체 설계는 **`계획/법령AI어시스턴트 설계도.md`** 에 있다. 이 기능을 건드리기
전에 반드시 읽는다. 요약:

1. **1단계 — 끝났다.** 법령 탭, PDF 업로드, 조문 단위 쪼개기, 낱말 검색(AND),
   조·쪽 원문 보기, 골라서 복사·저장.
2. **2단계 — 코드는 다 됐고 사용자가 열쇠를 넣으면 켜진다.**
   질문을 자연어로 적으면 관련 조문을 골라 주는 기능.
   Edge Function `law-pick`(Deno)이 Claude Haiku를 **두 번** 부른다 —
   ① 조문 제목 목록만 보고 후보 20개(이 목록은 캐시가 먹는다)
   ② 후보의 조문 전문을 읽고 최종 10개. 한 번에 50~150원.
   점수는 **세 판단의 합**이다(답이 여기 있나 / 인용이 꼭 필요한가 / 근거를 찾았나)
   + 법 위계 가산점. 시행 전 조문은 뺀다.
3. **3단계 — 아직.** Claude API로 민원 답변 초안 생성, 「민원 검토 서가」에 저장.
   한 건 약 90원. **2단계를 얼마간 써 본 뒤에 정한다.**

**전체 그림은 그려두되 구현은 1단계부터 차근차근** 진행한다.

### 2단계 — 켰다 (2026-09-04). 그때 겪은 것

- **npm 꾸러미를 쓰지 않는다.** `npm:@anthropic-ai/sdk` 를 불러오면 함수가
  깨어날 때 그걸 내려받다 시간이 넘어 `WORKER_ERROR`(500)만 난다. 프리플라이트
  (OPTIONS)까지 500이 되니 브라우저에는 「Failed to send a request to the Edge
  Function」으로 보인다 — 인증이나 CORS 문제로 보이지만 아니다. **fetch 로 직접
  부른다**(`api.anthropic.com/v1/messages`, PostgREST).
- **PostgREST 는 한 번에 1,000줄까지만 준다.** `limit=3000` 을 걸어도 소용없다.
  조문 1,289개 중 972개만 AI 에게 갔고 뒤쪽 법령은 아예 안 보였다. `pgAll()` 로
  나눠 가져온다. **화면에 「본 조문 972개」가 떠 있었는데도 몰랐다** — 숫자를 봤어야 했다.
- **`law_articles.id` 는 숫자다(32457).** `laws.id` 는 uuid 라서 헷갈린다.
  형 검사를 통과시키려고 한쪽에만 `String()` 을 붙였다가 **2차 AI 가 본문을
  하나도 못 받았다**(제목만 보고 답하니 「…있을 것으로 보입니다」). 낱말 보강도
  193개를 찾아 놓고 전부 버렸다. **열쇠는 한 가지 꼴로 통일한다.**
- **AI 가 낸 근거는 원문과 대조한다.** 「본문에서 그대로 옮긴 한 문장」을 내게 하고,
  빈칸을 지우고 원문에 있는지 검사한다. 없으면 「근거 찾음」을 내린다.
  짐작 말투(「있을 수 있」「가능성」)도 한 칸 내린다. **미리보기는 본문 앞 180자가
  아니라 그 근거 문장을 쓴다** — 앞 180자는 「붙임 1 제출자료 요건 ※…」처럼 아무 말도 안 한다.
- **1차는 조 제목만 본다.** 제목에 그 말이 없는 조는 통째로 빠진다. 그래서 1차에게
  **법령에 쓰일 낱말**을 같이 내게 하고(「생략」→「면제」「갈음」), 그 낱말로 본문을
  뒤져 후보에 보탠다. 「지침서는 제목만 봐도 걸린다」는 가정은 틀렸다 —
  1차가 새면 지침서도 통째로 놓친다. **그물은 전체에 친다.**
- **함수 배포는 Management API 로 할 수 있다.** 개인 액세스 토큰(`sbp_…`)으로
  `PATCH https://api.supabase.com/v1/projects/{ref}/functions/law-pick`
  (`{"body": 코드, "verify_jwt": true}`, **User-Agent 헤더 필수** — 없으면 403 1010).
  같은 토큰으로 `/api-keys?reveal=true` 에서 service_role 열쇠를 얻어 표를 직접
  들여다볼 수 있다. **토큰은 한 달짜리로 받는다(2026-09-30 이랑님 「1일 말고 한 달 하자」)** — 1일짜리는 며칠에 한 번씩
  401 이 나서 그때마다 이랑님 손을 빌렸다. 파일(`~/.yakktime-supabase-token`, 600)에만 두고, **만료 전에 내가 먼저 알린다**
  (`ls -l` 날짜 + 30일). 맥 일꾼은 이 토큰을 안 쓴다(service_role 열쇠 파일로 돈다).
- 시험은 함수를 직접 부른다: `POST .../functions/v1/law-pick` + publishable 열쇠.
  한 번 13~56원. 사용자에게 눌러 보라고 하지 않는다.
- **AI 가 JSON 을 안 내면 `stop_reason` 을 본다** (v133). `refusal`(거부) 은 다시 눌러도
  소용없고 `max_tokens`(잘림) 는 상한을 올리면 되는데, 예전엔 둘 다 「AI 답을 읽지
  못했어요」 하나라서 사용자가 계속 다시 누르게 됐다. `whyNoJson()` 이 갈라 안내한다.
- **AI 실패는 빨간 토스트가 아니라 결과 자리에 남긴다.** 토스트는 3초 만에 사라져
  원인을 읽을 틈이 없다. `{picks:[], stopped, note}` 로 돌려주면 화면에 남는다.
  「올려둔 법령에서는 못 찾았어요」(진짜로 없는 것)와 **뜻이 정반대**이므로 문구를 가른다.
- **원인 가설은 실측 전에 못 박지 않는다.** 「보툴리눔 독소라서 모델이 거부했다」가
  1순위 가설이었는데, 같은 질문을 그대로 넣어 보니 **성공했다**(122원, 조문 5건).
  가끔 나는 실패였고 원인은 2순위(`max_tokens: 700` 잘림) 쪽이었다.
  (**Haiku 는 안 거부한다. Opus 5 는 거부한다** — 같은 날 나중에 갈렸다. 아래 참조.)

### 모델을 어디에 쓰나 — 두 함수가 다르다 (2026-09-08 실측)

**`law-pick`(조문 찾기)은 Haiku 4.5, `law-draft`(답변 초안)는 Opus 5.5 다**(2026-09-30 Opus 5 → 5.5, 값 20% ↓, law-draft 15판. 첫 실측 14.5초·`via:"cli"`·0원 — 맥의 `--model opus` 도 이제 5.5 로 돈다. API 길은 월 한도 때문에 10-01 이후에 잰다).
둘 다 `MODELS` 표 + `CFG` 한 줄로 박아 뒀다. **요청 본문으로 모델을 고르게 두지
않는다** — 이 함수들은 앱 publishable 열쇠만 있으면 부를 수 있어서, 열어 두면
아무나 5배짜리 호출을 시킬 수 있다. 바꿀 때는 `CFG` 한 줄만 고친다.

질문 3개를 두 모델에 각각 넣어 재봤다 (약 2,200원).

| | Haiku 4.5 | Opus 5 |
|---|---|---|
| 실태조사 생략 | 41원 · 「의약품등 품목별 사전 GMP 평가 운영지침」을 **통째로 놓침** | 644원 · 그 지침 8·10·11쪽을 찾음(질문의 답 그 자체) |
| 시험 위탁 | 66원 · 5건 중 2건 근거 없음, 1건은 「별표 1 머리말」 | 421원 · 7건 **전부 원문 인용**(별표 17 7.3/7.4/7.5) |
| 보툴리눔 독소 | 86원 · 조문 7건 | 307원 · **거부(refusal, 6초)** |

- **조문 찾기는 Opus 가 확실히 낫다. 그런데 안 쓴다.** 한 번 307~644원이라 하루
  10건이면 월 10만원인데, Anthropic 월 한도가 $5(약 7,000원)다. **한도를 올린
  뒤에야 꺼낼 얘기다.** 올린다면 **거부당하면 Haiku 로 자동 재시도**하는 장치를
  같이 넣어야 한다 — 안 그러면 독소·병원체 질문이 통째로 막힌다.
- **초안은 Opus 다.** 여기서 AI 가 내는 건 요지 한 문장과 참고 두어 문장뿐이라
  **4원 → 23원**, 한 달에 500원도 안 든다. Opus 는 민원인이 실제로 물은 것을
  요지에 그대로 옮기고 참고에 **조 번호를 짚어** 적는다. **거부 위험도 없다** —
  조문 원문을 읽고 두 문장 쓰는 일이기 때문이다.
- **Opus 5 는 「생각하기」가 기본으로 켜져 있다.** `max_tokens` 가 생각한 양까지
  합쳐서 자르므로 모델 이름만 바꾸면 JSON 이 한복판에서 끊긴다. `room` 배수로
  자리를 6배 주고 `effort: "low"` 를 붙인다. **`effort` 는 Haiku 에 넣으면 오류**라
  Opus 일 때만 붙인다.
- **값 상수도 같이 옮긴다.** `IN_USD/OUT_USD` 를 Haiku 값으로 두고 모델만 바꾸면
  화면의 「이번 N원」이 5배 어긋난다. `usdOf()` 가 모델 설정을 받게 했다.
- **응답에 `model` 을 실어 보낸다.** 「왜 이런 답이 나왔지」를 따질 때 제일 먼저
  알아야 하는 것이 이것이다.

**거부하면 아래 모델로 자동으로 되받는다 (`law-draft`).** 「조문은 Haiku 로 찾고
초안만 Opus 로」가 될 줄 알았는데 **안 됐다** — 조문을 Haiku 가 멀쩡히 찾아 줘도,
그 조문으로 초안을 만들 때 **민원 글에 「보툴리눔 독소」가 들어 있으면 Opus 가
거부한다.** 거부는 빈 답으로 돌아오고 `law-draft` 에는 끝맺음 판별이 없어서,
**요지 칸만 비어 있는 초안이 조용히 나왔다**(117원 나가고 아무 말도 없음).
제일 알아채기 어려운 실패다.

그래서 `whyStop()` 을 붙이고, **Opus → (거부·잘림) → Haiku** 로 자동 되받게 했다.
좋은 모델을 먼저 쓰고 막히면 되받으므로 **사용자는 실패를 볼 일이 없다.**
되받았음은 `fellBack` 으로 화면에 알린다 — 조용히 갈아타면 「오늘은 왜 초안이
다르지」를 알 길이 없다. 값도 두 번 부른 만큼 합쳐서 보여준다(보툴리눔 143원).

**되받은 답은 품질이 떨어질 수 있다 — 실측에서 실제로 틀렸다.** 되받은 Haiku 가
「보툴리눔 독소는 **세포독성 항암제제**에 해당하므로」라고 썼다. **틀렸다**(생물학적
제제다). 같은 자리에서 Opus 는 「생물학적제제에 해당하므로」로 맞게 썼다.
**조문 원문은 브라우저가 넣으므로 틀릴 자리가 없지만, `help`(실무 참고)는 AI 가
쓰는 글이라 틀릴 수 있다.** 초안을 그대로 내보내지 말고 참고 줄은 눈으로 본다.

**2차 호출 `max_tokens: 2000` 도 잘리고 있었다 (v133 배포 뒤 실측에서 발견).**
아침에 1차만 700→1500 으로 올리고 2차를 안 올린 것이 화근이다. 후보 10개마다
`why` 와 `quote` 를 내므로 한 개에 200토큰쯤 들어, 어려운 질문이면 2000 을 넘긴다.
**6000 으로 올리니 실패하던 질문이 조문 7건을 냈다.** 안 쓰면 값은 그대로다.
**한 곳을 고치면 같은 이유로 옆의 것도 고쳐야 하는지 본다.**

### 2단계를 켜려면 (사용자가 할 일 · 아직 안 함)

1. Anthropic Console → Billing → **$5 충전 + 월 한도 $5**
2. API 키 만들기(`sk-ant-…`)
3. Supabase → Edge Functions → 새 함수 **`law-pick`** →
   `yakktime.com/law-pick.txt`의 코드를 붙여넣고 Deploy →
   **Secrets**에 `ANTHROPIC_API_KEY` 등록
4. 배포 뒤 **「조문 전부 다시 만들기」** 한 번

**열쇠 규칙 — 어기면 안 된다.**
- API 키는 **브라우저 코드·채팅창에 절대 두지 않는다.** Supabase Secrets에만 넣는다.
  GitHub 저장소가 public이고 `yakktime.com/app.js`는 누구나 볼 수 있다 —
  키가 한 번이라도 올라가면 몇 분 안에 봇이 긁어간다.
- **「Verify JWT」를 끄지 않는다.** 끄면 함수 주소만 아는 사람이 법령을 읽고 돈을 쓴다.
- 올리는 것은 **공개 법령·지침서만**. 민원 자료는 업체명·제조번호·이름을 지우고 올린다.
  AI에게 보내는 질문에도 개인정보를 넣지 않는다.

`supabase/functions/law-pick/index.ts`가 원본이고 저장소 뿌리의 `law-pick.txt`는
사용자가 복사해 붙이기 위한 사본이다. **`check-dup.sh`가 둘이 같은지 검사한다.**
사람에게 보이는 오류는 전부 **HTTP 200 + `{error}`** 로 돌려준다 —
supabase-js가 200이 아닌 응답의 본문을 넘겨주지 않기 때문이다.
