# 법령 받기·저장 — 법제처 API·별표 격자·맥에서 대신 올리기·복사

CLAUDE.md 에서 옮겨 온 기록이다(2026-10-14). 이 주제의 코드를 만지기 전에 읽는다.

## 법령·고시는 법제처 API 로 받는다 (v136~v140 · 2026-09-08 켰다 — 7개 전부 법제처 판)

지침서·안내서만 PDF 다. 법령·고시 7개는 법제처 OPEN API 에서 이름으로 받는다 — 개정되면
「조문 다시 만들기」 한 번으로 최신판이 따라오고, 별표의 표를 칸 그대로 읽는다.
Edge Function `law-fetch` 가 대행한다(검색·본문·별표 파일. AI 없음, 돈 안 듦. OC 는 Secrets `LAW_OC`).
브라우저가 본문 JSON 을 「쪽」으로 만들어 **`buildLawArticles()` 에 그대로 넣는다** — 그래서
라벨(제N조(제목) · 별표 N(제목) · 소제목 · 부칙 제N조 · 「· 시행 …」)이 PDF 판과 똑같다.
목록의 알림 한 줄(「법제처 판으로 바꾸기」)이 7개를 한 번에 바꾸고, 새 법령은 「법제처에서
이름으로 받기」로 파일 없이 받는다. 법령 표의 새 칸: `src`('api') `target` `mst` `lawcode` `fetched`
(`법령-법제처-컬럼추가.sql`).

- **「현행」은 `target=eflaw&efYd=시행일자` 로 받는다.** `target=law` 로 받으면 **시행예정판**이 온다
  (약사법 MST 279725 → 2026-11-12 판, 219조 전부 그 날짜). 그대로 쓰면 아직 시행 안 된 조문을
  현행으로 보여준다. eflaw 검색이 판마다 시행일자·현행/시행예정을 준다 — 「현행」 줄을 고른다.
- **시행예정 조는 앞 판과 다른 것만** 「[시행일: 2026. 11. 12.]」을 달아 넣는다(PDF 판과 같은 꼴).
  시행예정 판이 여럿이면 날짜순으로 앞 판과 견줘 **처음 나타난 날짜**에 붙인다. 최대 4판.
- **별표 목록은 본문 JSON 의 `별표단위`** 를 쓴다. 별표 검색 API(`licbyl`·`admbyl`, `search=2`)는
  「약사법」으로 찾으면 시행령·시행규칙 별표까지 섞여 온다.
- **별표 본문은 JSON 에도 있지만 표는 칸이 풀려 못 쓴다.** `별표서식파일링크`의 파일(고시 `.hwpx`,
  법령 `.hwp`)에 격자가 있다. 서식(별지)은 JSON 글자만 넣는다(체크 서식이라 읽힌다).
- **고시 조문은 한 조가 한 줄**이고 항·호가 붙어 온다(「…말한다.1. 다음의…」). `admrulBreaks()` 가
  ①·「N. 」·「가. 」 앞에서 줄을 끊는다. 고시 부칙은 `부칙단위`가 아니라 **`부칙공포일자[]`·
  `부칙내용[]` 두 배열**이다. 조가 없는 부칙은 안 넣는다 — 머리말이 없어 앞 조 꼬리에 붙는다.
- **조 제목은 80자까지 받는다(`ART_RE`).** 40자일 때 시설기준령 「제5조(페니실린제제, …
  세포독성 항암제제 작업소의 시설기준)」(61자)이 **PDF 판에서도** 통째로 빠져 있었다.
- **조문 행의 키는 전부 같아야 한다.** PostgREST 묶음 넣기는 행마다 키가 다르면 통째로 거부한다
  (PGRST102 「All object keys must match」). `tbl` 을 격자 행에만 넣었더니 규칙 410조가 **지워진 채**
  하나도 안 들어갔다(saveLawArticles 는 지우고 넣는다). 법제처 판은 `tbl:false` 를 모든 행에 넣는다.
- **부칙 쪽은 시행예정 쪽 뒤에** 둔다. 부칙 머리말 뒤의 조는 전부 「부칙 제N조」가 되므로(inBuchik),
  시행예정 조가 부칙 뒤에 오면 「부칙 제3조(약사 자격과 면허) · 시행 …」이 된다(약사법 21개가 그랬다).
- 실제 바꾸기(2026-09-08): 시설기준령 10조 2초 · 첨단재생법 72조 4초 · 약사법 234조 7초 ·
  규칙 442조(별표 16개 파일) 12초 · GMP 고시 260조 14초 · 생물 고시 116조 · 의약외품 고시 52조
  (별표 파일 48개 30초). 법제처가 막지 않았다. **7개 전부 법제처 판, 지침서 5개만 PDF.**
- **법제처 검색 결과가 1건이면 배열이 아니라 객체로 온다.** 고시 3개가 전부 그랬다 — `law-fetch` 2판.
- **이름은 일부만 적어도 된다 (v141).** 처음엔 정확한 이름을 요구했다가 「내가 전체 이름을 모르면
  못 찾잖아」를 들었다. 법령(eflaw)·고시(admrul)를 함께 찾아 **현행만** 후보로 보여주고(`lawCandsHtml`),
  누르면 받는다. 이미 올린 것은 흐리게. 후보가 40개면 「이름을 더 적으면 좁혀져요」.
- **법제처 판이 되면 PDF 파일은 지운다.** 쓸 데가 없다(「pdf 파일이 그대로 있을 이유가 있어?」).
  2026-09-08 저녁 7개 파일을 Storage 에서 지우고 `file_path` 를 비웠다. Storage 에는 지침서 5개만 남는다.
- 법제처 판은 쪽이 없다(`pages:0`). 카드의 쪽 배지·「쪽 그대로 보기」·「PDF 원문」 대신
  「법제처에서 보기 ↗」(`lawSiteUrl`). PDF 파일은 Storage 에 그대로 둔다.
- 실측(헤드리스 크롬, 파일 4개·본문 5개): 약사법 216행(조 212+부칙 4) · GMP 고시 261행 ·
  생물 고시 130행 · 규칙 456행(조 148·별표 199·별지 109). 빠진 조는 전부 「삭제」된 조.

**「조문 전부 다시 만들기」 버튼은 뺐다 (v152).** 이랑님: 「필요해?」 — 코드를 고쳐 다시 쪼개는 일은 내가 러너
(`scratchpad/uitest/runner2.html`)로 하고, 개정은 앱이 스스로 확인한다: 목록을 열면 법제처 판마다 검색 한 번
(`lawApiCheckUpdates`, 돈 안 듦)으로 현행 mst·시행일을 견줘 새 판이 있으면 「법제처에 새 판이 나왔어요 — 최신판으로
바꾸기」 알림 한 줄. 함수 `lawBuildAll()`·`lawReindex()` 는 남아 있다(러너와 「조문 만들기」 링크가 쓴다).

**올리기·받기는 목록 머리줄에 접었다 (v146).** 「법령 PDF 올리기」 배너가 탭 한복판에 크게 있었는데,
법령·고시가 법제처에서 오게 된 뒤로는 PDF 는 지침서 대여섯 개를 한 번 올리는 일이다. 이랑님이
「지금 PDF 올리는 창이 여기 탭에 있는 게 맞을까?」 → 늘 쓰는 것이 아니니 「올려둔 법령 N개」 머리줄
(전체 · 해제 · ＋ 법제처에서 받기 · PDF 올리기 · 조문 전부 다시 만들기)로 옮겼다. 법령이 하나도 없을 때만
큰 안내가 뜬다. `.upload-bar` CSS 는 남아 있다(죽은 CSS 정리 때 함께).

## 지침서 PDF 도 맥에서 대신 올린다 — tools/pdf_import.sh (2026-10-12)

이랑님 「지침서 없으면 추가로 다운 받아줘 … 앞으로도 부족하다 싶으면 먼저 제안하고 넣어줘」(기억 `feedback-fill-missing-sources`).
`sh tools/pdf_import.sh <pdf> "<앱에 보일 이름>"` — law_import.sh 의 진짜 Supabase 껍데기 위에서 `lawUpload(f)` 를 그대로 돌린다.
- **크롬은 매번 새 프로필 폴더로, `--virtual-time-budget`·`--dump-dom` 없이.** 가상 시계를 주면 pdf.js 가 읽기 전에 꺼져
  「PDF 읽는 중…」에서 멈추고, 쓰던 프로필을 또 쓰면 떠 있는 크롬에 주소만 넘겨 run.log 가 빈 채 끝난다(둘 다 10/12 실측).
  법제처 받기(law_import.sh)는 네트워크만 기다리는 일이라 가상 시계로도 됐던 것 — **PDF 는 CPU 일이라 다르다.**
- 끝나면 `sh tools/embed_slow.sh <lawId> …` 로 지문(Voyage 무료 3개/21초). 표로 잡힌 쪽이 많으면 `tools/tbl_fix.py prep·run·report·apply`
  (작업폴더 `~/.yakktime-uitest/tblfix_<이름>`, PyMuPDF 는 `pip --target 폴더/py`).
- 10/12 넣은 것: 「임상시험용의약품 GMP 평가 가이드라인[민원인 안내서]」(2022.10, 안내서-0057-02, 18쪽 — 식약처 게시판은 다운로드가 막혀
  제약바이오협회 미러에서 받음) + 고시 「의약품 임상시험 계획 승인에 관한 규정」(35조문). 지침서는 18쪽 중 14쪽이 표로 잡혀 tbl_fix 로
  전부 되살렸다(표 9 · 글 5, 빠진 글자 0.1% 이하). 넣고 나니 임상시험용 제조시설 민원에서 8쪽·10쪽이 **인용 필수**로 올라왔다.

## 별표의 표는 격자로 저장하고 화면이 표로 그린다 (v136)

표는 글자 속에 **「┃칸│칸│칸┨」 한 줄**로 넣는다. 공백 손질(`\s+`→" ")을 견디고 법령 글에 안 쓰는
기호라, 검색·복사·AI 는 그대로 글자를 보고 **화면만** 표로 그린다(`gridSplit`·`gridHtml`).
- hwp(CFB)는 `cfbOpen()`(FAT·미니FAT·디렉터리 트리)으로 `BodyText/SectionN` 을 꺼내고 레코드를
  걷는다: 77 TABLE(행·열 수는 **offset 4·6**) → 같은 level 의 72 LIST_HEADER 가 칸(col·row·colspan·
  rowspan 은 offset 8부터 UINT16 ×4) → 더 깊은 67 PARA_TEXT 가 칸 글자. **제어 문자(1~3·11·12·14~18·
  21~23 확장, 4~9·19·20 인라인)는 8글자를 차지한다** — 안 건너뛰면 「捤獥 汤捯」가 낀다.
  hwpx 는 zip 안 `Contents/section0.xml` 을 정규식으로 걷는다(`hp:tbl`·`hp:tc`·`cellAddr`·`cellSpan`).
- **hwpx 의 `<hp:t>` 안에는 `<hp:tab/>` 같은 꼬리표가 섞여 있다.** 안 떼면 「<hp:tab width="4000" …/>」가
  본문에 그대로 새어 나온다(GMP 고시 별표 2의2, v142 에서 잡음). 탭·줄바꿈은 빈칸으로, 나머지 꼬리표는 뗀다.
- **압축은 직접 푼다(`inflateRawSync`, puff 알고리즘).** `DecompressionStream("deflate-raw")` 은
  hwp 스트림 끝의 꼬리 바이트를 오류로 보고 **「Failed to fetch」** 를 낸다 — fetch 문제로 보이지만
  아니다(파이썬 zlib 은 그냥 풀린다). 구형 사파리에는 아예 없다. zip 도 같은 함수로 푼다.
- **폭 전체를 병합한 칸 하나짜리 줄은 문단**(제목·일반기준)이고, 머리 줄은 첫 줄 + 첫 칸이 빈
  채로 이어지는 줄(「│ │ 1차 │ 2차 │」)이다. **표 하나가** 4,500자를 넘으면 줄 단위로 토막 내고
  토막마다 머리 줄을 다시 붙인다 — 어느 토막이든 표로 읽힌다. 토막 이름은 첫 자료 줄의 첫 칸.
  작은 표가 여럿인 글 별표는 토막 내지 않고 `subHeads` 로 나눈다(`gridSafe` 가 줄 안 자름점을 뺀다).
- 검색 결과에서 격자 줄 안의 낱말은 **그 줄 전체 + 머리 줄**을 작은 표로 보여준다(`gridRowsInfo`).
  글 조각은 표 줄을 삼키지 않게 줄 경계에서 자른다. 복사는 「칸 | 칸 | 칸」(`lawPlain`).
- 격자 행은 `tbl=false` 다 — 읽을 수 있는 표이므로 「칸이 뒤섞여…」를 띄우지 않는다.
- 실측: 규칙 별표 8(행정처분) 345행×6열 → 9토막 · 격자 깨짐 0 / 약사법 시행령 별표 2 48×6 /
  첨단재생법 시행령 별표 3 19×5 / GMP 고시 별표 1(hwpx) 표 6개.

## 마스터 문서(민원 자료) 코드는 걷어냈다 (v136)

`ref*` 함수 30여 개·`renderRefs`·파일 입력칸을 지웠다(app.js 5,607 → 5,251줄). **표(`refs`·`ref_parts`)와
`TABLES` 항목은 그대로**다(백업 보존). 남긴 것: `zipEntryText`(옛 `extractDocXml` — hwpx 가 쓴다),
`markTerms`(표 칸의 형광펜), `isRefTitle`(조문 판별이 쓴다). `check-refs.py` 가 딸려 지워지는 것을 막았다.

## 검색 결과를 복사할 때 — 발췌가 아니라 조항 전문

「전부 복사」·「텍스트로 저장」은 화면의 짧은 발췌(`…제외하고...`)가 아니라
**검색어가 든 항(①)을 통째로** 담는다. 민원 답변에 그대로 붙여야 하기 때문이다.
`lawBlockRange()`가 항 → 호 → 목 순으로 내려가며 덩어리를 잡고, 지침서처럼
층이 없는 글은 앞뒤 문장 경계까지 넓힌다(`sentRange()`). `lawPlain()`이
화면의 「원문 보기」와 같은 들여쓰기로 평문을 만든다.

**검색어가 없는 항은 담지 않는다.** ②항까지 딸려오면 답변에 없는 내용이 섞인다.

**「쪽 그대로 보기」는 앞뒤 쪽에서 잘린 문장 조각을 이어 붙인다.** PDF는 문장
한복판에서 쪽을 넘기므로 「우 정지 1 개월 정지 3 개월」처럼 꼬리부터 시작하는 쪽이
나온다. `edgeBits()`가 앞 쪽의 마지막 문장 꼬리와 다음 쪽의 첫 문장 머리만 가져와
**흐리게** 붙인다(`.lv-edge`). 표는 문장 끝이 드물어 그냥 두면 조각이 최대치까지
늘어나 정작 그 쪽 내용을 밀어내므로, 앞 180자·뒤 110자로 끊는다.
