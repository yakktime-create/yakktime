## 실태조사 노트 (v165 · 2026-09-10)

GMP 실사 현장에서 아이패드로 들고 다니는 노트. 이랑님: 「간단하게 들고 다니는 노트가 됐으면 해. 표시하고 적을 거거든.」
**실사 한 건 = 노트 한 권**, 페이지 여섯 장(준비·일정·현장·서류 검토·방·발견 — v166). v165 의 아홉 장(일차·질문·내 담당 페이지)은
같은 것을 두 번 묻고 현장·서류가 섞여 하루 만에 갈았다(이랑님 「UX/UI 가 너무 안 좋은 것 같아 … 현장 질문과 호텔에서 서류 볼 때를 구분」).
**날·내 담당·건물은 페이지가 아니라 거르기(`inspFilter`)다.** 현장 줄은 「보기」(kind task)·「묻기」(kind q), 일정 줄의 서류 요청은 kind doc. 법령 탭과는 잇지 않았다
(이랑님: 「법령 탭이랑 연결되는 건 별로 없을 거야. ICH·PIC/S 정도」) — 발견의 「근거」는 손으로 적는 칸.

- **표:** `inspections`(노트) · `insp_items`(줄. `kind` = task·doc·q·room·find, `page`, `section`, `seq`, `building`, `area`,
  `done`, `memo`, `grade`, `ref`, `src`). SQL `실태조사-테이블추가.sql`(Management API 로 돌림).
- **본(템플릿)은 `insp_template.json`** — 이랑님 체크리스트 + 별첨 1-5 실태조사(GMP) 45항목 + 「조사관의 눈」(원액 공정별 보기·묻기).
  125줄, `version` 으로 판을 가른다. `insp.tpl` 이 다르거나 옛 페이지 줄이 있으면 노트 위에 「새 본으로 다시 채우기」 띠(`inspRefill`:
  본에서 온 줄은 갈고 같은 글의 체크·메모는 옮기며, 직접 적은 줄·방·발견은 남긴다). 줄에 `day`(d1·d2·d3) 칸이 있다. 새 노트는 이걸 복사한다(`inspCreate`, 항목은 한 요청으로 묶어 넣음).
  캘린더에 기간 일정(`until`)도 같이 넣는다.
- **내 담당 페이지**는 `insp.areas` 에 든 영역의 줄을 모아 보인다. 업무분장이 바뀌면 영역 칩을 켜고 끈다.
- **줄을 누르면 메모 칸**, **길게 누르면(600ms) 「발견」으로**(`inspToFind`). 방·발견은 늘 펼쳐진 자유 줄(이름 + 메모, 발견은 등급·건물·근거).
- **오프라인:** `sw.js`(network-first 껍데기 캐시 — 새 판이 막히지 않는다) + `insp_cache`(localStorage) + `inspQ`(못 올린
  쓰기 줄, `insp_queue`). `loadAll` 이 실패한 표는 캐시로 채우고(`inspApplyCache`), 온라인이 되면 `inspFlush`. 머리줄 「저장 대기 N」.
  **오프라인 시험은 아직 실제 기기로 못 했다** — 다음 주 실사 전에 아이패드 비행기 모드로 한 번 열어 볼 것.
- 2단계(아직): 발견 한글 내보내기 · 「본으로 복사」 · 방 사진.
- 시험대: `?insp=new` · `?insp=make&page=tour|review|plan|rooms` · `&find=1`.
