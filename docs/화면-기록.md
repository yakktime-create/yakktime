# 화면 손질 기록 — 오늘·캘린더·첫 탭 문제·토스 결 적용 내역

CLAUDE.md 에서 옮겨 온 기록이다(2026-10-14). 이 주제의 코드를 만지기 전에 읽는다.

## 첫 탭이 안 먹는 두 가지 원인 (v226 · 2026-10-12)

이랑님 「별표 처음 일정 생성하면 안 눌리던데 다른거 눌렀다가 눌러야 … 취소도 두 번 … 전반적으로 많은데」.
1. **새 줄을 id 없이 먼저 그렸다.** `S.x.unshift(item); render(); dbInsert()` 순서라 첫 그림의 `data-id` 가 비어 있었다(v160 은 dbInsert 안에서
   uuid 를 박지만 render 가 앞이었다). ★·✕·체크는 id 로 줄을 찾으니 첫 탭이 허탕, 아무거나 눌러 다시 그리면 그때부터 됐다.
   **새 항목은 `dbInsert()` 를 먼저 부르고 `render()`.** 여섯 곳을 바꿨다(할 일·기고글·식약처 업무·일정·출장·그날 업무).
2. **고치는 칸의 blur 가 그 자리에서 render 했다.** 탭 순서는 pointerdown → blur → click 이라, blur 에서 그리면 click 이 노린 버튼이
   사라져 두 번 눌러야 한다. `startEdit` 의 blur 저장을 220ms 미뤘다(실사 메모 300ms 와 같은 꼴). `editingId` 는 즉시 풀어 다른 칸은
   바로 열리고, 그 사이 다른 칸을 열었으면 render 대신 원래 글자 자리로 되돌린다.
**입력칸 blur 에서 render() 를 부르는 코드는 전부 이 위험이 있다** — 새로 만들 땐 미루거나(setTimeout 200~300ms) 결과 칸만 바꿔 끼운다.

## 새 항목의 열쇠는 브라우저가 만든다 (v160 · 2026-09-09)

새 할 일을 넣고 바로 ✕ 를 누르면 「삭제 실패: invalid input syntax for type uuid: "undefined"」가 났다(이랑님 「x 누르면
한 번에 안 지워짐」). 화면은 요청 전에 먼저 그려지는데 그때는 id 가 없어서 ✕ 가 `"undefined"` 를 지우려 했다.
`dbInsert()` 가 `uuid()` 로 열쇠를 미리 만들어 넣는다 — 표 여섯 개(schedule·events·articles·mfds·laws·answers) 모두
uuid 기본값이라 넣어 주면 그대로 받는다(2026-09-09 Management API 로 확인). 서버 응답의 id 는 있을 때만 덮는다.

**「언젠가 할 일」(v160).** 오늘 탭 맨 아래, 날짜 없는 할 일(`due` null). 「앞으로 할 일」은 날짜가 있어야 하니 「나중에 언젠가」
가 갈 데가 없었다. `dueOf()` 의 「null 은 오늘」 규칙은 옛 자료 호환용이었는데 실측 0건이라 null = 언젠가로 바꿨다.
`addSchedule(SOMEDAY, …)` 가 null 로 넣는다.

## 오늘 화면 = 캘린더의 오늘 (v212 · 2026-09-28)

「오늘 일정」 카드가 `dayListHtml(todayKey)` 를 그린다 — 캘린더 날짜 칸과 **같은 함수**다(`calEvRow` · `calTaskRow` · `isTripEv`,
`renderCalendar` 앞). 그래서 여러 날짜리 출장(맨 위) · 기한이 오늘인 식약처 업무(체크 상자·상태) · 일정 · 메모·장소·지도 ·
누르면 그 자리에서 고치기가 두 화면에서 똑같다. 예전엔 오늘 **시작하는** 일정만 보여서 출장 중·오늘 기한 업무가 빠졌다
(이랑님 「캘린더에서 오늘 해당하는 것들도 오늘 화면에」). 머리글의 「오늘 일정 N건」도 같은 셈(완료한 업무는 뺌).
「기간 고치기」(`trip-edit`)는 캘린더에서만 되므로 오늘 화면에서 누르면 그 달력으로 데려간다.
**한 날의 줄 모양을 고칠 땐 이 함수 하나만 고친다** — 두 화면이 어긋나지 않는다.
**일정에도 완료 체크가 있다 (v235 · 2026-10-12).** 이랑님 「식약처 업무 아닌 것도 동그라미 체크해서 취소선」. `events.done`(boolean, `일정-완료-컬럼추가.sql`,
Management API 로 더함) — `calEvRow` 가 출장·여행이 아닌 일정에 `day-check`(`ev-done`)를 달고, 끝낸 줄·달력 칩은 취소선, 「오늘 일정 N건」에서 뺀다.
**오늘 화면에서는 출장을 뺀다**(`dayListHtml(key,true)`, v213 — 이랑님 「출장만 빼자」: 며칠씩 맨 위에 눌러앉아 그날 할 일이 안 보인다). 캘린더에는 그대로.

## 글자는 토스처럼 (v155 · 2026-09-09 이랑님 요청)

- 본문 한 치수 위로: `--fs-md` 13→14 · `--fs-base` 14→15 · `--fs-lg` 15→16 · `--fs-xl` 17→18. `body` 에 기본 크기·자간·줄간격을 걸었다.

- **세리프(Georgia) 제목을 없앴다** — 한 글꼴로 간다. 제목은 굵기(750)와 자간으로 세운다.
- **위계는 셋만**: 제목(굵고 큼) / 본문 / 보조(작고 흐림). 법령 카드의 조 이름은 노란 알약이 아니라 **굵은 글자**(`.law-art`),
  등급·근거·「답변에 씀」 표시는 `--fs-xs`·700 으로 한 단 조용하게. 법령 묶음 머리말은 파란 채움을 빼고 글자+위계 색 띠만.
- **조 이름의 「·」은 화면에서 세로줄로**(v158): 「별표 17 · 5.2 …」의 가운뎃점이 번호와 제목 사이에서 안 보였다(이랑님).
  `lawArtHtml()` 이 첫 「 · 」만 `.law-art-sep`(연한 |)로 그린다. **저장된 라벨·검색·복사·답변은 「·」 그대로다.**
- **한글 줄바꿈은 낱말 단위**(v156): `body{word-break:keep-all;overflow-wrap:anywhere}`. 기본은 글자 단위라 부제가 「답 / 변」으로
  끊겼다(이랑님 「위에 줄바뀜 왜 일어나는거야?」). 빈칸 없는 긴 글(격자 줄·주소)만 아무 데서나 끊는다. `.page-sub` 폭 46→60ch.
- 확인: 900·620·1040 스샷(법령 AI 결과·낱말 결과·오늘·캘린더) 깨진 곳 없음. 달력 칩(`--fs-2xs/xs`)은 안 건드렸다.

## 화면을 고치기 전에 — UI 재설계 계획

탭·스타일을 손대는 작업은 **`계획/UI 재설계 계획.md`** 를 먼저 읽는다. 요약:

- 탭 7개 → 6개, 세 묶음(**일정** / **업무** / **자료**). 없애는 건 **문서 인덱스**
  하나뿐이고, 나머지는 왼쪽 메뉴에 묶음 머리말만 붙인다. **표(DB)는 안 건드린다** —
  `docs` 표도 지우지 않고 화면만 없앤다.
- **기고글은 서울시약사회 업무라 식약처 업무와 합치지 않는다.** 모양이 같다고
  합치지 않는다 — 합칠지는 화면이 아니라 그 일이 누구의 일인지로 정한다.
- 「위치만 적어 두기」(docs의 link/cat)는 **쓰지 않아서 버린다.** 안 쓰는 기능은
  옮기지 말고 버린다.
- CSS에 **간격·글자크기·모서리 토큰이 없다**(색만 있음). 그래서 화면마다 값이
  제각각이다. 숫자를 직접 적지 말고 토큰을 먼저 늘린다.
- 순서: ① 토큰·부품 통합 → ② 탭 재배치 → ③ 화면 다듬기 → ④ 죽은 CSS 제거.
  **UI 재편이 끝난 뒤에 법령 AI 2·3단계로 간다** (AI 답변이 「검토 서가」에
  들어가는데 서가 구조가 바뀔 예정이라 두 번 만들게 된다).
- 팔레트는 바꾸지 않는다. 프레임워크도 넣지 않는다.
